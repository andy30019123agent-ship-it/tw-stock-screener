# 勝率榜多時間窗（近3月／近半年／近一年／歷史）

**日期**：2026-07-24
**需求（Andy）**：勝率榜可以點選近一個月／近三個月／近半年／近一年／歷史勝率，想想怎麼呈現與優化。
**Andy 拍板**：「1+2」＝並列多時間窗表格（一眼看趨勢）＋欄位可點聚焦排序。

## 一個決定形狀的技術限制

勝率的定義是「進場後 20 個交易日的報酬」。所以**最近約 20 個交易日的訊號還沒有結果可算**
（要再等 20 天才知道漲跌）。這代表：

- **「近一個月」窗幾乎必然是空的**——不是 bug，是「答案尚未揭曉」。列了只會給一個樣本數趨近 0
  的假數字。**故砍掉近1月**，最短從近3月起。
- 這跟 2026-07-23 踩到的「28 天樣本騙人」是同一個坑：短窗的數字不可信。

## 設計

### 資料（後端）
- 母體＝`bt_price.json` 長歷史（約兩年、478 交易日）。這是能算多窗的前提，短歷史做不出來。
- **`collect_events()` 只跑一次**（逐檔重算指標，是最重的部分）；各窗只是「按日期篩事件」再
  套 `events_to_stats`／`stats_to_weights`，近乎零額外成本。
- **每窗的基準（同日全市場平均）只用該窗內的日期**——近3月的超額要跟近3月的大盤比，不能被
  歷史平均污染。
- 窗（曆日，從最新資料日 `as_of` 往回）：近3月=90、近半年=180、近一年=365、歷史=全部。
- 產出 `pipeline/signal_windows.json`（signals-major：`{sigkey:{label, 3m,6m,1y,all}}`，
  每格含 `avg_excess / excess_win_rate / samples / validated / weight`）。由 `ensure_weights`
  每週重算時寫；`opportunities.run()` 每天複製到 `public/data/`（抓不到就靜默略過，不硬性依賴）。
- **不動選股引擎**：機會股 Top5 仍用 `signal_weights.json`（＝歷史全窗權重）排序，這次只是加一份
  透明化展示資料。

### 呈現（前端 Opportunities.jsx）
- 一列一訊號、橫向四欄（近3月｜近半年｜近一年｜歷史）。
- 每格：主數字＝平均超額 pp（紅漲綠跌，守 MASTER 色彩鐵則），次行＝超額勝率％·樣本。
- **欄位標題可點**→ 切換排序聚焦（該欄高亮、依該窗平均超額排序）。預設聚焦「歷史」。
- **↑↓ 趨勢箭頭**：近半年 vs 歷史平均超額（差 ≥0.1pp 標↑、≤−0.1pp 標↓，兩者都要夠樣本才判）。
- **樣本不足（<30）整格轉灰＋提示**「僅供參考」——避免拿雜訊嚇人。
- 表下一行列出「目前生效權重」（歷史窗 weight>0 者），保留 Andy 原本看得到的權重資訊。
- 缺 `signal_windows.json` 時退回舊的單欄勝率表（漸進增強，不讓沒資料時開天窗）。

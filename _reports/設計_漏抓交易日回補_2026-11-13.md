# 設計：漏抓交易日自動回補（2026-11-13）

## 一句話

以前每天只抓「今天」，哪天抓失敗那天就永遠空著；現在每天抓完後多做一件事——拿證交所官方的「這個月哪幾天有開盤」清單對照我們的歷史，少了哪天就回頭補抓，一次最多補 3 天，補不到的記下來隔天再試。

## 白話比喻

像記帳本：以前每天只記當天的帳，某天忘了就整頁空白。現在每晚記完，會翻開銀行對帳單（官方交易日清單）對一下最近 20 天，發現哪天空白就去把那天的收據（吃日期的全市場資料）找回來夾進正確的頁數，不是貼在最後一頁。找不到收據的那天不會亂填，只在便利貼上寫「待補」。

## 設計取捨

1. **「應有交易日」用 TWSE FMTQIK，不用 index.json。** 加權指數（index.json）是跟個股同一步抓的，每日那步失敗時它也一起缺——實際查過，08-18～08-20 index.json 同樣沒有。FMTQIK 是另一個端點，當天失敗不影響它事後列出那天；它還附當天加權指數收盤，順便補 index.json，不用多打請求（已比對 08-14、08-17、08-21、08-24 四天，跟 index.json 現有數值完全一樣）。
2. **自動只看最近 20 個交易日。** 20＝法人歷史保存天數（更舊的洞補了法人也會被修剪），大約 4 週，夠蓋過長假期間連續失敗；基準只要抓 1～2 個月，每天多 2 個請求。更舊的洞（像 08-18～08-20）用手動輸入補。
3. **每次最多補 3 天、每個請求間隔 2 秒。** 每天最多多 3×4＋2＋2＝16 個請求，避免被限流；沒補完的下次接著補。
4. **整天全有或全無。** 一天要寫進去，必須上市、上櫃 OHLCV 都夠多檔（上市 ≥500、上櫃 ≥300；正常約 1,090／860 檔），落在法人保存期內的還要兩市場法人都拿到，再加上同期間的除權息事件兩市場都拿到。任何一塊失敗或回空 → 那天一個 byte 都不寫，標「待補」。理由：寧可缺，不要寫半套——半套比缺更難發現。
5. **除權息也要補。** 每日流程是「抓當天除權息事件」，那天失敗事件也漏了（實查 08-18～08-20 dividends.json 是 0 筆，前後幾天每天 5～13 筆）。漏掉事件會讓還原權息算錯，把除息當成真實下跌。
6. **插入正確位置，不是接在最後。** 每檔股票的日期仍保持遞增、不重複；滾動視窗照原規則截（price 每檔 110 天、法人 20 天、指數 110 天、bt_price 500 天）——插進一天就從最舊那頭掉一天。
7. **寫檔順序固定：除權息 → 法人 → 指數 → bt_price → price。** price.json 是判斷「哪天缺」的依據，放最後寫。萬一中途被打斷，price 還沒有那天，下次一樣判成缺口，整天重抓重寫（重寫同一天是覆蓋，不會重複）。每個檔本身是原子寫入，不會寫一半壞掉。
8. **bt_price.json 當下就寫，不等每週合併。** 原本 bt 是每週從 price.json 補新日期；回補直接寫 bt，08-18～08-20 這種比 price 視窗還舊的洞也補得進去，兩邊當天就一致。
9. **失敗安全分兩層。** 網路／資料類預期錯誤（逾時、回空、JSON 壞掉）在每一天各自處理、記待補。非預期錯誤（程式錯誤、官方改格式）由最外層保護殼接住：印完整錯誤訊息、寫進狀態檔 `last_error`，但不往外丟——當天的正常更新、build、部署、TG 照常。程式錯誤靠測試直接呼叫沒有保護殼的 `run()` 抓出來。
10. **連續失敗 10 次就停止自動重試**（例如 TWSE 對某天永久回空，2024-09-24 遇過），列在 `gave_up`，標明「未解決」，不算已處理；手動指定那天會重新給機會。

## 已知限制

- **自動只看最近 20 個交易日**，更舊的洞要手動輸入。
- **基準本身抓不到時那個月不判斷**：FMTQIK 被限流回空，那個月的缺口當天看不到，等基準恢復後才會發現（不會誤判成休市，也不會標成已處理）。
- **「今天」的洞要等明天才補**：只檢查到歷史裡最新那天為止。今天抓失敗時，前端照舊顯示過期警告（fetch_ok 旗標沒動）；明天抓到新的一天後，今天就變成「中間的洞」被補上。
- **既有的另一個洞沒處理**：STOCK_DAY_ALL 若回「前一天」的資料（官方還沒更新），每日流程會重寫前一天、照樣標 fetch_ok＝True，今天就漏了。這次回補會在下一個交易日把它補回來，但 fetch_ok 那時不會顯示警告。
- **回測權重、層級統計最多晚一週才用到新資料**（每週重算閘門）；想馬上看，手動跑一次並勾 `force_recompute`。成績單、交易日曆、RS、指標每天重算，下一次執行就用到。
- **TWSE 對某天永久回空時**，這支補不了，要改用 `finmind_fill.py --dates`。

## 怎麼確認它有在運作

1. **看 Actions log**：「每日累積最新交易日＋漏抓交易日回補」那步會印 `🩹 漏抓回補：歷史最新 …、基準月份 OK […]；缺口 N 天`，有補就印 `本次補好 N 天 [...]`。
2. **看狀態檔** `pipeline/backfill_state.json`（每天跟著 commit 回 main）：
   - `backfilled`：補過哪些日子、什麼時候補的、上市／上櫃各幾檔、來源（永久累積，方便日後追查）
   - `pending`：還在等的日子、試了幾次、最後一次的錯誤
   - `gave_up`：放棄自動重試的日子
   - `baseline.months_failed`：基準抓不到的月份（有值＝當天沒能完整檢查）
   - `last_error`：非預期錯誤（有值就要找工程師看）
3. **補 08-18～08-20**：到 GitHub Actions → 這個 workflow → Run workflow，「手動回補漏抓的交易日」填 `2026-08-18:2026-08-20`，其他不勾。跑完狀態檔的 `backfilled` 應出現這三天。

## 🟡 中等問題

### 1. 快速套用卡「全天候」徽章與長訊號名稱在 375 寬會逐字斷行

- **寬度**：375
- **重現步驟**：首頁 → 不用任何互動，「本週市況建議卡」預設就顯示。往下看第 5 項訊號「縮口帶量突破」。
- **現象**：訊號名稱「縮口帶量突破」（6 字）與旁邊「全天候」徽章在窄欄擠壓下逐字換行，變成「縮口帶量突／破」「全天／候」，兩者都斷成兩行、排版難看。前 4 個訊號（4 字名稱：強勢雙確認／強勢股60日／多頭排列／爆量突破）不會斷，只有長度較長的這一項會斷。
- **截圖**：`_audit_screenshots/375_top5expanded.png`
- **根因**：`src/App.css` 第 389–394 行，`.ma-list li` 是 flex row（`.ma-name` + `.ma-exc` + `.ma-apply`），但 `.ma-name`／`.ma-tag` 都沒有 `white-space: nowrap` 或 `flex-shrink` 控制，右側 `.ma-apply` 又有 `min-width: 64px`（第 397–399 行），擠壓下 `.ma-name` 被迫換行，CJK 無空格就逐字斷。對應元件：`src/components/MarketAdvice.jsx` 第 55–58 行。
- **修法**：給 `.ma-name` 或其內部文字節點加 `white-space: nowrap` + 讓整個 `li` 允許換行到下一行（`flex-wrap: wrap`），或把 `.ma-tag` 移到訊號名稱下方另起一行，避免同一行塞「長名稱＋徽章＋數字＋按鈕」四個元素。

### 2. 五張數據表在手機寬度沒有 sticky 首欄，橫向捲動會看不到是哪個策略/組合

- **寬度**：375（768／1280 皆因欄位總寬 < 容器寬，不會觸發橫向捲動，不受影響）
- **重現步驟**：展開「篩選條件」→ 展開「各策略回測戰績」（或「組合戰績排行榜」「新訊號研究」「出場分析」「市況分層」）→ 在表格區域向右滑動。
- **現象**：實測 `.strategy-scroll` 內容寬 628px vs 容器 301px、`.combo-scroll` 596px vs 301px，確實需要橫向捲動。捲動後左側「策略／組合名稱」欄完全滑出畫面（`getComputedStyle` 確認 `position: static`，非 sticky），只剩數字欄，使用者看不出這排數字是哪個策略。截圖 `_audit_screenshots/375_strategy_table_scrolled.png` 可見捲動後畫面只剩「樣本外／中位數／贏大盤／平均超額」等數字欄，沒有策略名稱可對照。
- **根因**：`src/App.css`
  - `.strategy-table th:first-child, .strategy-table td:first-child`（第 356 行）只設 `text-align:left`，沒有 `position: sticky; left: 0;`
  - `.combo-table .combo-name`（第 432 行）同樣沒有 sticky
  - 對照組：同檔案第 279 行 `.wq-table .wq-sig` 已經有正確寫法（`position: sticky; left: 0; background: var(--surface); z-index: 1;`），可以直接套用同樣寫法到這兩個 class。
  - 桌機版熱力圖 `.combo-heat`（第 478–479 行）已經做對了（`tbody th { position: sticky; left: 0 }`），只有這 5 張手機會橫向捲動的表格漏掉。
- **修法**：比照 `.wq-sig` 的寫法，給 `.strategy-table th:first-child/td:first-child` 與 `.combo-table .combo-name` 加 `position: sticky; left: 0; background: var(--surface); z-index: 1;`。

# 回測「Top5 選股程序」本身 — 2026-07-25

**做法**：唯讀重播。用 `pipeline/history/bt_price.json`（479 交易日、1,504 檔）＋ `dividends.json`／`chip.json`／`universe.json`，
對每個歷史交易日逐股跑 `build_data.compute_indicators(pr[:i+1])`（PIT，無前視）＋ `backtest_signals.build_xsect_cache`（PIT 橫斷面 RS），
然後**原樣重播** `opportunities.build_opportunities()` 的決策鏈（門檻 → 量能 → 計分 → 排序 → 取 5），
量測這 5 檔往後 20 交易日的**成本後超額** = `_apply_cost(個股毛報酬) − 同日全市場平均毛報酬`（來回成本 0.7831%，與專案其他地方同一把尺）。

**主分析窗＝2025-02-05 ~ 2026-06-25，339 個交易日。**
為什麼不是 479 天：`rs_confirmed_60_120` 需要 121 根 K 線的橫斷面，bt_price 前 120 天算不出來 → 門檻在
2025-02-05 之前**從未生效過**（56 天全部退回全市場）。把那段算進去等於在評估「沒套門檻的程序」。
全窗（395 日）數字併列在下面供對照。

> ⚠️ 這把尺的「零技巧水位不是 0，是 −0.80pp」：全市場等權（≥300 張、960 檔）成本後超額 = **−0.800pp**
> （中位 −0.802、395/395 天為負、sd 0.05）。因為分子扣成本、分母（大盤基準）不扣。看任何數字都要先減這條線。

## Q4. 門檻退回機制（候選 < 20 就取消門檻）觸發過幾次？

- 全窗 395 天觸發 **58 次**，但其中 **56 次是回測暖身期的假觸發**（2024-11-07 ~ 2025-02-04，
  `rs_pct_120` 需要 121 根 K 線，bt_price 前 120 天算不出來 → 全市場沒有任何一檔過得了門檻）。
- **真正的觸發只有 2 天：2025-04-25（合格候選 18 檔）、2025-04-28（18 檔），兩天都是黃燈。**
- 那兩天的表現：**−13.49pp 與 −12.27pp**——是全期最差的日子之一。
- 暖身期後（2025-02-05 起）合格候選數：中位 **69**、最小 18、最大 132。**2026 年至今 113 個交易日，退回 0 次。**

**判定**：`GATE_MIN_POOL=20` 這個保命機制在 1.4 年裡只啟動過 2 天（0.6%），
而那 2 天剛好是「市場剛崩完、強勢股只剩 18 檔」——機制的效果是「在最不該放寬的時候放寬」。
但 **n=2，不能下統計結論**。可靠的部分是：它幾乎不會觸發，所以它不是風險來源，也不是價值來源。
真正的風險是它**靜默失效**：如果 RS 資料抓取掛掉，`gate.reason` 會標 `rs_unavailable`——這條路徑我沒有測試（見「無法驗證」）。

## 🚫 無法驗證的部分（缺什麼資料）

1. **🔴「營收年減剔除」完全無法回測**。`pipeline/revenue_cache.json` 只有**一個當期快照**
   （`fetched_month: "2026-07"`、單一 `data_ym`，見 `monthly_revenue.py:6-8` 的快取設計：同一日曆月沿用、
   每月覆蓋），沒有任何歷史月份。TWSE/TPEX 的 `t187ap05` OpenAPI 只回最新一期。
   → 本報告所有數字都是「**沒有營收濾網**」的版本。這條規則對績效的貢獻**至今零證據**，
   而它會**每天真的剔除股票**。
   **需要的證據**：逐月營收 YoY 歷史（FinMind `TaiwanStockMonthRevenue`，或逐月抓 MOPS t187ap05 存檔），
   至少回溯到 2024-08 才能和現有 479 天價格對齊。**從今天起每月存一份快照**是最便宜的補救（現在的覆蓋邏輯會直接覆蓋掉）。
2. **rs20 只能用「數學等價的代理」重播**。`history/index.json` 只有 **2026-05-28 起 39 個交易日**，
   而 `compute_indicators` 的 `rs20` 需要加權指數（回測時 `collect_events` 傳 `index_series=None`
   → 歷史上 rs20 恆為 None）。
   我用「個股自己的 20 日還原報酬」排序：因為 `rs20 = 個股20日報酬 − 指數20日報酬`，
   而**同一天指數報酬對所有股票是同一個常數**，所以**排序結果完全等價**。
   殘留差異：production 的 rs20 用「個股與指數的共同交易日」對齊，停牌股的起訖日會差一兩天（極少數）。
3. **「乖離大」風險旗標**只加標記不剔除，不影響選股，故未評估。
4. **`gate.reason = rs_unavailable` 路徑未測**（RS 抓取失敗 → 門檻靜默失效）。這是程式碼路徑問題，
   不是統計問題，需要用注入式單元測試驗。
5. **權重的輕微前視已處理**：另跑了「走前權重」版本（每日只用已成熟事件重算 ENGINE 權重，公式同 `stats_to_weights`）
   → 全窗 **+2.927pp、中位 +2.020、勝率 58.0%、t(NW) = 2.38**，比用現行權重的 +2.473 還好。
   **結論：權重前視沒有膨脹結果。** 但 `sn_squeeze_breakout` 之所以是唯一有權重的訊號，
   本身是用這段歷史選出來的 → 前後半期檢查：score=1 子集 前半 +1.678 / 後半 +3.750（Top5 前半 +1.672 / 後半 +4.102）。
   **兩半都是正的，但後半是前半的 2.2~2.5 倍——邊際隨時間放大，很可能是行情（AI 大型股）而非訊號。**
6. **存活者偏誤**：bt_price 只有 1,504 檔、universe 是 2026-06-26 的**現存**名單，期間下市的股票兩邊都沒有。
   方向上是**保守的**（被剔掉的多是輸家，會把基準拉高、把 Top5 的超額壓低），但無法量化。
7. **可交易性**：貢獻第 4 名的 **7610 聯友金屬-創（+514pp，佔全部超額 10.5%）是創新板股票**（`universe.json` 標「上市」）。
   → **待確認**：Andy 的券商帳戶當下能不能買創新板（需簽風險預告書／專業投資人條件）。
   需要的證據：券商下單頁面實測或 TWSE 現行創新板投資人資格規定。若不能買，全部數字要扣掉這 10.5%。

### 🔴 證據強（多個獨立指標同向、統計上站得住）

**1. `TOP_N = 5` 應該提高到 10~20（或至少讓使用者知道 5 檔的雜訊有多大）。**
證據：5 / 10 / 20 檔的平均幾乎相同（+2.89 / +3.37 / +3.22），但
sd 12.34 → 9.28 → 6.46、中位 +0.98 → +1.53 → **+2.56**、日勝率 54% → 59% → **68%**、t(NW) 1.83 → 2.70 → **3.43**、
不重疊複利最大回撤中位 −27.3 → −18.8 → **−10.8pp**、最差 offset 累計 −21.2% → +7.6% → **+30.2%**。
**5 檔沒有任何一項指標贏過 10 或 20 檔。**這是全報告最乾淨的結論。
（實務限制：Andy 的部位級距是 10/20/40 萬，20 檔不現實 → 建議 TOP_N=10，或維持 5 但改用下面第 2 點的排序。）

**2. `rs20` 不該當排序依據。**
證據：(a) 配對隨機對照 t=0.28、0/20 seed 顯著；(b) 反向排序 t=2.72 > 現行 1.83；
(c) score=1 內部五分位 Q5−Q1=1.00pp 而 SE 1.2~1.6、且不單調；(d) 換 `rs_pct_60` 每項都更好。
**建議**：改用 `rs_pct_60`（+3.56 / 中位 +2.82 / t 2.17），或乾脆不排序、把 score=1 的候選全部等權後取前 N。
**注意**：`rs_pct_60` 的優勢也不顯著（配對差 −0.67，t=−0.52）——這是「換一個一樣沒被證明、但每項指標都不差的」，
不是「換一個被證明的」。若要保守，就承認排序層無證據，改成「score=1 候選全列出、不排名」。

**3. 「營收年減剔除」必須先補資料再談要不要留。**
證據：`revenue_cache.json` 只有當期快照 → 至今零證據，卻每天真的在剔除股票。
**建議**：(a) 立刻開始每月存一份 `revenue_cache` 快照（成本近零，不然永遠補不回來）；
(b) 在補到 12 個月以上歷史之前，網頁上不要把它寫成「已驗證的濾網」。

### 🟡 證據中等（方向清楚但效果量小或樣本受限）

**4. `MIN_VOL_LOTS = 500` 是重複過濾，可以刪掉（或至少寫清楚它不是這裡在擋）。**
證據：`build_data.py:633` 的 `--min-vol` 預設已是 500，`results` 進 `build_opportunities` 時就 ≥500；
把門檻降到 0 只有 12.1%（41/339）的日子選出的股票有變、平均差 +0.10pp（t=0.73）。
**不建議降低**（中位數會從 +0.975 掉到 +0.673），但要知道它幾乎沒在做事。

**5. 門檻 `rs_confirmed_60_120` 改變 58.4% 日子的選股卻零績效貢獻（+0.03pp，t=0.06），但別急著拿掉。**
它跟 rs20 排序重複；一旦照第 2 點改掉排序，門檻就會變成主要的強勢過濾，重要性會回來。
**建議**：改排序和改門檻**不要同時做**，否則兩個都拿掉會退回 +1.43pp（整池隨機水位）。

**6. `GATE_MIN_POOL = 20` 的退回機制：1.4 年只真正觸發 2 天（2025-04-25 / 04-28），那兩天 −13.5pp / −12.3pp。**
n=2 無法下結論。**建議**：不改邏輯，但那天的輸出要在前端明講「今天強勢股不足、這批是全市場技術面最佳、風險較高」
（目前 `gate.applied=false` 有傳到前端，但沒有語氣上的降級）。

### 🟢 證據弱／只是揭露（不必改程式，但必須讓使用者看到）

**7. 「score（縮口帶量突破）當篩子」是整條鏈裡唯一被證據支持的排序/計分決策**
（score=1 子集 +2.714 / 中位 +2.614 / 勝率 69.4% / t=3.04 vs score=0 +0.619 / t=0.85）。
但它作為「排序第一鍵」沒有增量（因為 60.1% 的純 rs20 選股本來就有它）。
**建議**：把它從「加分項」明確變成**第二層篩子**（像 rs_confirmed 那樣），而不是排序鍵。

**8. 必須在畫面上揭露的三個數字（現在完全沒有）：**
- 單檔推薦的**中位數是 −2.14pp、勝率 46.4%**（一半以上的推薦扣成本後輸大盤）。
- 全部超額的 **83.6% 來自 8 檔**（395 檔不重複裡的 8 檔）。
- **對 0050 沒有可偵測的優勢**（+1.43pp，t=0.69）。
不揭露這三件事，「平均超額 +2.9pp」會被讀成「照這個買每個月多賺 2.9%」，而真實體驗是
「大部分時候小輸，偶爾中一支大的」。
